# 第一章 概述

回忆路线：编译、解释、JIT   C++编译过程   编译全过程  

## 1. 为什么学习编译原理

1. 计算机生态不断变化，需要编译技术适配新的环境（如新语言、新硬件、新应用）
2. 理解高级语言程序的内部机制
3. 培养形式化与抽象能力

## 2. 编译器

**定义**：编译器是一种**系统软件**（系统软件的作用是为其他软件提供运行或开发平台）

**功能**：将**源程序**翻译成语义等价的目标程序（源程序 -> 目标程序）

## 3. 编译、解释、JIT、AOT

### 3.1 编译

广义定义：将**源程序**翻译成语义等价的**目标程序**，再运行目标程序（本课程的定义）

狭义定义：目标程序限定为机器语言

特点：

- 移植性：生成独立目标程序，目标程序的移植性通常较差
- 性能：运行时性能较好
- 灵活性：修改源程序后需要重新编译，灵活性较差
- 优化：容易进行全局优化

典型语言：

- C
- C++

### 3.2 解释

定义：不生成独立机器目标程序，边运行边解释

特点：

- 移植性：不生成机器目标程序，通常源程序的可移植性较好
- 性能：运行时性能较弱
- 灵活性：修改源程序后不需要编译，灵活性较好
- 优化：较难进行全局优化（因为只看到局部）

典型语言：

- Python
- Ruby

### 3.3 JIT 运行时编译

定义：Just-In-Time Compiler，即运行时编译。程序运行过程中进行编译，可保存已翻译的机器代码，供下次使用。

特点：

- 灵活性和性能：兼具解释器的灵活性和接近 AOT 的性能
- 优化：可以根据运行时信息进行动态优化

典型例子：

```text
Java 源代码
   ↓ 编译
字节码 .class
   ↓ JIT（运行时编译）
机器代码
```

### 3.4 AOT 编译

AOT：Ahead-Of-Time，即运行前编译。即传统编译，同3.1。

## 4. AOT编译的具体例子：C语言

C 程序从 `hello.c` 到可执行文件 `hello`，通常经历四个阶段。

### 4.1 预处理 Preprocessing

输入：hello.c

输出：hello.i

主要工作：展开宏定义、处理头文件包含、处理条件编译

命令示例：

```bash
clang -E hello.c -o hello.i
```

### 4.2 编译 Compiling（内部包含完整的编译6阶段）

输入：hello.i

输出：hello.s

主要工作：将预处理后的 C 程序翻译为汇编代码、可能中间代码为 LLVM IR

命令示例：

```bash
clang -S hello.i -o hello.s
```

### 4.3 汇编 Assembling

输入：hello.s

输出：hello.o

主要工作：将汇编代码翻译为机器指令、生成可重定位目标文件

命令示例：

```bash
clang -c hello.s -o hello.o
```

### 4.4 链接 Linking

输入：hello.o

输出：hello

主要工作：链接库函数和其他目标文件、生成最终可执行文件

命令示例：

```bash
clang hello.o -o hello
```

### 5.1 前端与后端

#### 5.1.1 前端 Front End / Analysis

前端负责分析源程序，主要检查源程序的正确性。

包括：

1. 词法分析
2. 语法分析
3. 语义分析

#### 5.1.2 后端 Back End / Synthesis

后端负责生成目标程序，主要负责高效实现目标程序。

包括：

1. 中间代码生成
2. 代码优化
3. 目标代码生成

### 5.2 编译各阶段详解

#### 5.2.1 词法分析 Lexical Analysis

输入：源程序字符流

输出：Token 序列

主要工作：从左到右扫描源程序，将字符流分解成有意义的单词或符号，判断是否符合词法规则

Token 通常表示为：<类别, 属性值>

常见 token：关键字、标识符、常量、运算符、分隔符

#### 5.2.2 语法分析 Syntax Analysis

输入：Token 序列

输出：语法树 Syntax Tree

主要工作：判断 token 序列是否符合语言文法，识别表达式、语句、程序结构、构造语法分析树

#### 5.2.3 语义分析 Semantic Analysis

输入：语法树

输出：语法树 + 符号表

主要工作：在语法正确的基础上检查语义是否正确，收集标识符属性信息，检查类型、作用域、声明与使用关系

符号表中常见信息：变量名，类型 type，作用域 scope，存储位置等

语义错误例子：

```text
变量未声明就使用
变量重复声明
函数声明和使用不一致
使用未定义函数
数组下标越界
除数为 0
int x; y = x(3);
```

#### 5.2.4 中间代码生成 Intermediate Code Generation

输入：语法树

输出：中间表示 IR

主要工作：将源程序初步翻译成中间表示，在源语言和目标机器语言之间建立桥梁，方便后续优化和目标代码生成

常见 IR：三地址码 TAC

#### 5.2.5 代码优化 Code Optimization

输入：IR

输出：优化后的 IR

主要工作：对中间代码进行等价变换。使代码更短、更快或更省内存

#### 5.2.6 目标代码生成 Target Code Generation

输入：优化后的 IR

输出：目标代码（可能是机器代码，也可能是汇编代码）

主要工作：为特定机器生成目标代码：进行寄存器分配、选择机器指令、做机器相关优化 

# 第二章 语言和文法基础

回忆路线：概念（语言、语法、语义、文法）形式定义（符号 符号集 符号串 符号串集合 运算 文法 产生式 句型 句子 文法类型 语法树 句柄 句型分析）

本章为通用概念，在词法分析和语法分析章节中有不同的具体体现：

| 通用概念      | 词法分析              | 语法分析                  |

| 符号          | 单字符                | token的词素               |
| 字母表/符号集 | 单字符集合            | token的类别集合           |
| 符号串        | 字符串                | token的词素组成的句子     |

## 1. 概念：语言和文法

### 1.1 语言

程序设计**语言**包括：**语法**和**语义**。

**语法**：**一组规则**，用来形成和产生合法的程序。

**语义**：**定义程序的意义**，分为静态语义和动态语义

- **静态语义**：程序在语义上要遵守的规则，例如类型、声明、作用域等规则
- **动态语义**：程序运行时实际要做什么

### 1.2 文法

**定义**：文法是**语法的描述工具**，用有限的规则描述语言中可能无限的句子集合。

## 2. 形式定义：符号、符号集、符号串及其运算、符号串集合及其运算、语言

同义词：符号/元素、符号集/字母表、头/前缀、尾/后缀

PS：字母表 / 符号集 Σ 可看作符号串集合（符号串长度为1）

### 2.1 符号集/字母表

**定义**：符号的非空有穷集合。

例子：Σ = {0, 1}，A = {a, b, c}。

### 2.2 符号串

**定义**：符号串是由符号集/字母表中的符号组成的任何有穷序列。

**特点**：1.有顺序 2. 不含任何符号的符号串称为空串，记为 ε

**长度**：构成符号串长度的个数|abc| = 3，|ε| = 0。

例子：若 Σ = {0, 1}，则 0、00、10、011 都是 Σ 上的符号串。

### 2.3 符号串的头、尾、固有头和固有尾

设符号串 z = xy。

- x 是 z 的头，也就是前缀
- y 是 z 的尾，也就是后缀
- 若 y 非空，则 x 是 z 的固有头，也就是真前缀
- 若 x 非空，则 y 是 z 的固有尾，也就是真后缀

例子：z = abc

z 的头：**ε**, a, ab, abc

其中固有头：**ε**, a, ab

z 的尾：**ε**, c, bc, abc

其中固有尾：**ε**, c, bc

### 2.4 符号串的运算

#### 2.4.1 连接

**定义**：设 x 和 y 是符号串，它们的连接 xy 是把 y 写在 x 后面得到的符号串。

空串对连接的影响：εx = xε = x

例子：若 x = ST，y = abu，则 xy = STabu。

#### 2.4.2 方幂

**定义**：符号串的方幂是把符号串自身连接若干次。

例子：a^0 = ε，a^1 = a，a^2 = aa。

若 x = AB，则 x^0 = ε，x^1 = AB，x^2 = ABAB。

### 2.5 符号串集合及其运算

#### 2.5.1 符号串集合

**定义**：若集合 A 中所有元素都是某字母表 Σ 上的符号串，则称 A 为字母表 Σ 上的符号串集合。

#### 2.5.2 集合乘积

**定义**：符号串集合 A 和 B 的乘积为：AB = {xy | x ∈ A 且 y ∈ B}

例子：

```text
A = {ab, cde}
B = {0, 1}

AB = {ab0, ab1, cde0, cde1}
```

空串集合对乘积的影响：{ε}A = A{ε} = A

#### 2.5.3 集合方幂

**定义**：设 A 是符号串集合，则 A^i 表示符号串集合 A 的方幂。

其中：A^0 = {ε}，A^1 = A，A^2 = AA，A^k = AA...A（共 k 个 A）。

例子：若 A = {a, b}，则 A^0 = {ε}，A^1 = {a, b}，A^2 = {aa, ab, ba, bb}。

#### 2.5.4 集合闭包和正闭包

PS：也是一种集合的运算（作用于集合）

##### 2.5.4.1 闭包

**定义**：集合 Σ 的闭包 Σ* 为：Σ* = Σ^0 ∪ Σ^1 ∪ Σ^2 ∪ Σ^3 ∪ ...

含义：Σ* 表示 Σ 上所有有穷长符号串的集合，包括空串 ε。

例子：若 Σ = {0, 1}，则 Σ* = {ε, 0, 1, 00, 01, 10, 11, 000, ...}。

##### 2.5.4.2 正闭包

**定义**：集合 Σ 的正闭包 Σ+ 为：Σ+ = Σ^1 ∪ Σ^2 ∪ Σ^3 ∪ ...

含义：Σ+ 表示 Σ 上除 ε 外的所有有穷长符号串。

关系：Σ* = Σ^0 ∪ Σ+，Σ+ = ΣΣ* = Σ*Σ。

### 2.7 语言（字母表产生的语言）

**定义**：字母表 Σ 上的语言，是 Σ* 的任意子集（是个符号串集合）

也就是：L ⊆ Σ*

例子：Σ = {a, b}

以下都是 Σ 上的语言：

- {a^n b^n | n ≥ 1}
- {a^n | n ≥ 1}
- {ε}
- ∅

## 3. 形式定义：文法、句型、句子、语言

PS：终结符和非终结符都是符号集/字母表中的符号

PS：通常约定，大写字母为单个非终止符，小写字母为单个终止符，希腊字母为符号串

PS：产生式是单箭头，推导过程才是双横线箭头

### 3.1 文法

**定义**：文法 G 是一个四元组：G = (VN, VT, P, S)

其中：

| 组成 | 含义 | 说明 |
|---|---|---|
| VN | 非终结符集（符号集） | 可以继续推导出其他符号串 |
| VT | 终结符集（符号集） | 不可以继续推导 |
| P | 产生式的集合 | 也叫规则集合 |
| S | 开始符号 | 推导的起点 |

要求：

- VN、VT 和 P 是非空有穷集
- VN ∩ VT = ∅
- V = VN ∪ VT，**V** 称为文法 G 的**字母表**（两个符号集的并集）
- S ∈ VN
- S 至少要在一条产生式的左部出现

### 3.2 产生式

**定义**：产生式是一个有序对，通常写作：α -> β（这里两者都为符号串）

其中：α ∈ **V+**，且 α 至少含有一个非终结符；β ∈ **V***

总结，两个限制：

1. 左边不能是空串
2. 左边必须有至少一个大写字母（非终止符）

### 3.3 文法的简化表示

实际写文法时，通常不完整写出四元组，只写产生式。

约定：

- 默认第一条产生式左部的符号是开始符号
- 也可以用 **G[S]** 表示 S 是开始符号
- **大写字母**或尖括号表示**非终结符**
- **小写字母**通常表示**终结符**
- 左部相同的产生式可以**合并**

### 3.4 推导和归约

定义：字符串之间的一种关系

- =>：一步推导（反过来就是规约）
- =>+：一步或多步推导
- =>*：零步或多步推导（可以相等）

### 3.5 句型、句子和语言

#### 3.5.1 句型

**定义**：若从开始符号 S 可以推导出符号串 α，即：**S =>* α**，则称 α 是文法 G[S] 的**句型**。（一种符号串，由字母表中符号构成）

（PS：从S经过任意步退出来的东西）

#### 3.5.2 句子

**定义**：若 α 是句型，并且 α 只由终结符组成，即 S =>* α 且 α ∈ VT*，则称 α 是文法 G[S] 的**句子**。（一种符号串，由字母表中的终结符号构成）

（PS：从S经过任意步推出来的东西，但必须全部由终结符/小写字母组成，或者是空串）

关系：句子一定是句型，句型不一定是句子。

#### 3.5.3 文法产生的语言（区别于2.7字母表产生的语言）

**定义**：文法 G[S] 的一切**句子**的集合称为文法 G 产生的语言，记作：L(G)（本质：符号串集合）

形式化表示：L(G) = {w | S =>* w 且 w ∈ VT*}

例子：

```text
G[S]:
S -> 0S1
S -> 01
```

可以推导出：S => 0S1 => 00S11 => ... => 0^n1^n

所以：L(G) = {0^n1^n | n ≥ 1}

### 3.6 文法的等价

**定义**：若两个文法**产生的语言相同**，则称两个文法**等价**。

形式化表示：L(G1) = L(G2)，则：G1 和 G2 等价

注意：文法不同，不代表语言不同。

## 4. 文法的类型

Chomsky 将文法分为四类：0 型文法、1 型文法、2 型文法、3 型文法。

它们的限制逐渐增强：0 型文法 ⊇ 1 型文法 ⊇ 2 型文法 ⊇ 3 型文法

### 4.1 0 型文法（短语文法）

产生式形式：α -> β

总结限制：

1. 左边不能是空串
2. 左边必须有至少一个大写字母（非终止符）

特点：

- 任何文法都是 0 型文法

### 4.2 1 型文法（上下文有关文法）

产生式形式：αAγ -> αβγ，（A ∈ VN，α, γ ∈ V*，β ∈ V+）

总结限制：

1. 左边不能是空串
2. 左边必须有至少一个大写字母（非终止符）
3. 产生式右部长度大于等于左部长度，S -> ε 除外

含义：只有当 A 处在上下文 α 和 γ 中时，才能把 A 替换成 β。

### 4.3 2 型文法（上下文无关文法）

产生式形式：A -> β，（A ∈ VN，β ∈ V*）

总结限制：

1. 左边不能是空串
2. 左边必须有至少一个大写字母（非终止符）
3. 左边就是一个大写字母（非终止符）

含义：不管 A 出现在什么上下文中，都可以把 A 替换成 β。

特点：

- 程序设计语言的语法结构通常用 2 型文法描述
- 本章后续重点讨论上下文无关文法

### 4.4 3 型文法（正规文法）

产生式形式：A -> aB 或 A -> a （A, B ∈ VN，a ∈ VT）

特点：

- 3 型文法是 2 型文法的特例
- 在程序设计语言中，通常用来描述单词的结构
- 和后续词法分析关系密切

### 4.5 算符文法

算符文法不是 Chomsky 四型文法中的新一类，而是上下文无关文法中的一种特殊限制形式。

**定义**：若一个上下文无关文法中，任一产生式右部都不含两个相邻的非终结符，并且不含 ε 产生式，则称为算符文法。

总结限制：

1. 必须是上下文无关文法
2. 产生式右部不能出现两个相邻非终结符
3. 不含 ε 产生式

作用：

- 为后续算符优先分析做准备
- 适合描述部分表达式结构
- 通过终结符之间的优先关系指导移进和归约

PS：算符文法的重点不是“文法属于第几型”，而是它的右部结构适合定义终结符之间的优先关系。

## 5. 上下文无关文法及其语法树

### 5.1 上下文无关文法 CFG

上下文无关文法有足够的能力描述程序设计语言的语法结构。

典型例子：算术表达式文法。

```text
E -> E + T | T
T -> T * F | F
F -> (E) | i
```

其中：

- E 表示表达式
- T 表示项
- F 表示因子
- i 表示标识符或常量

### 5.2 最左推导和最右推导

**最左推导**：在推导的每一步，总是替换当前句型中的最左非终结符。

**最右推导/规范推到**：在推导的每一步，总是替换当前句型中的最右非终结符。

由规范推导得到的句型称为**规范句型**，也称为**右句型**。

### 5.3 语法树

**作用**：直观描述**上下文无关文法**的句型推导过程（表示一个句型/句子）

给定文法 G = (VN, VT, P, S)，若一棵树满足以下条件，则称为 G 的语法树：

1. 每个结点都有一个标记，标记是 V 中的一个符号
2. 根结点的标记是开始符号 S
3. 若一个结点有子孙，则该结点的标记一定是非终结符
4. 若结点 A 的直接子结点从左到右为 A1, A2, ..., Ak，则 A -> A1A2...Ak 一定是 P 中的产生式

语法树的叶子结点从左到右读出的符号串，就是该语法树对应的句型。

注意：语法树只能表示推导结构，看不出推导时替换非终结符的先后顺序。

### 5.4 文法的二义性

**定义**：如果一个文法存在某个**句子**对应两棵不同的语法树，则这个文法是二义的。

等价理解：某个句子存在两个不同的最左推导/最右推导

## 6. 句型的分析

PS：规范分析：自上向下分析，最右推导；自下向上，最左直接规约（句柄）

PS：不一定对句子分析，句型就可以分析

### 6.1 句型分析

定义：识别输入符号串是否为语法上正确的程序的过程。

任务：识别一个符号串是否为某文法的句型或句子。

从推导角度看，若 S =>* α，则 α 是文法 G[S] 的句型。

从语法树角度看，若能根据文法构造出 α 的语法树，则 α 是该文法的句型。

两类基本方法：

- 自上而下分析法
- 自下而上分析法

### 6.2 自上而下分析

**定义**：从文法的开始符号出发，反复使用产生式，寻找与输入符号串匹配的推导。

**语法树构造方向**：从根结点 S 开始，向叶子结点构造。

主要**问题**：如何选择产生式。

### 6.3 自下而上分析

**定义**：从输入符号串开始，逐步进行归约，直到归约到文法的开始符号。

**语法树构造方向**：从叶子结点开始，向根结点 S 构造。

主要**问题**：如何确定当前应该归约哪个子串。（PS：这个应该被归约的子串称为**句柄**）

### 6.4 短语、直接短语和句柄

设 αβδ 是文法 G[S] 的一个句型。

#### 6.4.1 短语

S **=>*** αβδ，S **=>*** αAδ，A **=>+** β

则称 β 是句型 αβδ 相对于非终结符 A 的**短语**（本质是句型中的一个子串）

即，条件为：

1. αβδ 是文法的句型
2. αAδ 也是文法的句型
3. A 可以推导出 β

PS：短语需要指定特定的句型，每个句型可能包含多个短语；句型就可以有短语，不需要是句子；需要A一步或多步推导

#### 6.4.2 直接短语 Simple Phrase

上述基础，如果有：A => β（一步产生）

也就是 A -> β 是一步产生式，则称 β 是相对于规则 A -> β 的**直接短语**。

直接短语也称为**简单短语**。

#### 6.4.3 句柄 

**定义**：一个句型的**最左直接短语**称为该句型的**句柄**。

作用：句柄就是自下而上分析中的可归约串。

因此，自下而上分析的核心问题就是：如何正确找到**句柄**。

### 6.5 短语与语法树的关系

短语、直接短语、句柄可以通过语法树识别。

方法：写先出句型的语法树，然后从上到下找子树，子树的根就是大写字母，所有叶节点就是一个短语。层高为1就是直接短语。

## 7. 文法实用中的限制

### 7.1 有害规则

**定义**：形如下面的规则称为有害规则：U -> U

特点：

- 对产生句子没有实际作用
- 可能引起文法分析问题

### 7.2 多余规则

**定义**：所有句子推导过程中都用不到的规则称为多余规则。

#### 7.2.1 不可到达

某些非终结符无法从开始符号推导到。

也就是不存在：S =>* αAβ

则 A 在句子推导中无法被使用。

#### 7.2.2 不可终止

某些非终结符无法推导出终结符号串。

也就是不存在：A =>* t

其中 t ∈ VT*。

### 7.3 有用非终结符的条件

一个非终结符 A 真正有用，需要同时满足：

1. 可**到达**：S =>* αAβ
2. 可**终止**：A =>* t，其中 t ∈ VT*

### 7.4 ε 规则

上下文无关文法中允许使用：A -> ε（右边可以为空）

这种产生式称为 ε 规则。

# 第三章 词法分析

## 1. 概念：词法分析基本概念

### 1.1 词法分析

**定义**：词法分析是扫描源程序字符流，识别并分解出token的过程。

输入：源程序字符流

输出：token 序列

主要工作：

1. 去掉无意义内容，例如注释、空白符
2. 将字符流划分为一个个 token：类别和属性值

### 1.2 token

**定义**：token 是词法分析中的最小意义单元，表示为：<类别，属性值>

其中：

- **类别**：例如keyword、identifier、number、operator
- **属性值 / 词素**：即该 token 在源程序中对应的具体字符串

常见 token 类别：

- 标识符：getBalance、weight
- 保留字：if、else、while
- 常量：10、3.14、"abc"
- 运算符：+、-、*、/、<<
- 界符 / 标点：括号、分号、冒号

### 1.3 词法分析器

词法分析器也称为 **Scanner** 或 **Tokenizer**，作用：进行词法分析

### 1.4 词法分析中的歧义问题和解决

常见问题：

- == 应该识别为一个运算符，还是两个 =？
- if 应该识别为关键字，还是标识符？
- C++ 中 >> 可能是流操作符，也可能是两个连续的 >

常用处理：

1. **最长匹配原则**：优先选择能匹配的最长词素
2. **关键字表**：先按标识符识别，再查表判断是否为关键字
3. **向前看 look ahead**：必要时查看后续输入，但应尽量减少向前看的数量

## 2. 词法规范

词法规范：描述 token 类别对应的字符串集合。

常见词法规范：

1. 表达式：正则表达式 / 正则定义
2. 文法：正规文法（3 型文法）
3. 有穷自动机（DFA / NFA）

### 2.1 正则表达式 / 正则定义

#### 2.1.1 基本定义与规则

**定义**：正则表达式，也称正规式，用来描述语言（字符串集合），正则表达式所描述的语言称为**正规集**。

基础规则：

1. ε 和 ∅ 是正规式，L(ε) = {ε}，L(∅) = ∅
2. 若 a ∈ Σ，则 a 是正规式，L(a) = {a}
3. 若 r 和 s 是正规式，则 r|s、rs、r* 也是正规式

其中：

- r|s 表示选择，L(r|s) = L(r) ∪ L(s)
- rs 表示连接，L(rs) = L(r)L(s)
- r* 表示闭包，L(r) = L(r)*

优先级：括号 > 闭包 * > 连接 > 或 |

#### 2.1.2 正则表达式的常用扩展

常用表达：

- A+ 表示一个或多个 A，等价于 AA*
- A? 表示可选，等价于 A|ε
- [abc] 表示 a|b|c
- [a-z] 表示从 a 到 z 的字符范围
- [^a-z] 表示不在 a 到 z 范围内的字符

常见例子：

- a*：零个或多个 a
- a+：一个或多个 a
- (a|b)*：所有由 a 和 b 组成的串，包括 ε
- (a|b)(a|b)：长度为 2 的 a/b 串
- [0-9]：一个数字字符
- (0|1)*00(0|1)*：包含子串 00 的二进制串

#### 2.1.3 用正则表达式描述C语言中的token

例子：

- 关键字：if | else | then | for
- 数字：digit digit*即digit+ PS：这里允许前导0
- 标识符：letter(letter | digit)*   PS：不能以数字开头
- 空白符：(blank | tab | newline)+

其中：

- digit 可以定义为 0|1|2|...|9
- letter 可以定义为 a-z 和 A-Z 范围内的字母

PS：C 语言标识符还允许下划线，因此更接近 (_|letter)(_|letter|digit)*。

#### 2.1.4 正则定义

正则表达式是“直接写规则”；正则定义是“给规则起名字，再组合规则”。

### 2.2 正规文法

正则表达式和正规文法都可以描述正规语言。

区别：

- **正则表达式**更适合直接描述 token 的构成规律
- **正规文法**更接近文法产生式形式
- 实践中通常用**正则表达式**自动生成词法分析器

### 2.3 有穷自动机

PS：正则表达式/正则文法是词法定义/规范，自动机是实现（判断字符串是否属于正则表达式定义的语言）

#### 2.3.1 转换图

转换图由状态和边组成。

结点：状态

- 初始状态：只有一个，一般由没有出发结点的箭头指向
- 接受状态 / 终止状态：可以有多个，通常用双圈表示

边：有向边，边上标记输入符号。

含义：若当前处于状态 S，且下一个输入符号是 a，则沿着从 S 出发、标记为 a 的边转移。

#### 2.3.2 有穷自动机 FA

**定义**：有穷自动机是具有有穷个状态、用于识别字符串是否属于某个语言的机器或程序。

一个有穷自动机是五元组：M = (S, Σ, δ, s0, F)

其中：

| 组成 | 含义 |
|---|---|
| S | 有穷状态集合 |
| Σ | 输入字母表 |
| δ | 状态转换函数 |
| s0 | 初始状态，且 s0 ∈ S |
| F | 接受状态集合，且 F ⊆ S |

**接受字符串的条件：**

如果存在一条从初始状态到某个接受状态的路径，并且路径上边标记连接成的字符串等于输入串 x，则称 x 被该自动机接受。

FA 接受的所有字符串集合，就是该 FA 识别的语言。

PS：NFA更容易由正则表达式得到，可以有多个接受状态

#### 2.3.3 DFA

**定义**：DFA 是确定的有穷自动机。

特点：

- 任意时刻只能处于一个状态
- 每个状态对每个输入符号最多对应一个确定转移
- 没有 ε 转移
- 对一个输入串，只会走一条路径

接受条件：存在某一条路径在输入结束时到达接受状态，就认为 NFA 接受该输入串。

转换函数：δ: S × Σ -> S （每个状态+当前输入字符->下一个状态）

#### 2.3.4 NFA

**定义**：NFA 是不确定的有穷自动机。

特点：

- 任意时刻可以理解为同时处于多个可能状态
- 同一状态对同一输入符号可以有多个转移
- 可以有 ε 转移
- 对一个输入串，可能存在多条路径

接受条件：只要存在某一条路径在输入结束时到达接受状态，就认为 NFA 接受该输入串。

转换函数：

- 普通 NFA：δ: S × Σ -> 2^S（S的幂集）
- ε-NFA：δ: S × (Σ ∪ {ε}) -> 2^S

## 3. 转换：RE->NFA->DFA->Table

### 3.1 总流程

词法分析器的自动生成流程：

正则表达式RE -> NFA -> DFA -> 表驱动实现

### 3.2 RE 转 NFA

RE 转 NFA 通常采用 Thompson 构造算法。

输入：字母表 Σ 上的正则表达式 r

输出：接受 L(r) 的 NFA

基本思想：递归处理正则表达式的子表达式。

原子规则：

- ε：构造一条 ε 转移
- a：构造一条标记为 a 的转移

组合规则：

- s|t：增加新开始状态和新接受状态，通过 ε 转移连接 s 和 t
- st：把 s 的接受状态接到 t 的开始状态
- s*：增加新开始状态和新接受状态，并通过 ε 转移支持重复和跳过

PS：Thompson 构造通常会产生 ε-NFA。

### 3.3 NFA 转 DFA

NFA 转 DFA 使用**子集构造法**。

核心思想：DFA 的一个状态对应 NFA 的一个状态集合。

也就是说：

- NFA 同一时刻可能处于多个状态
- DFA 用一个状态集合来表示这些可能状态

#### 3.3.1 ε-closure

**定义**：状态集合 I 的 ε-closure(I)，是 I 中所有状态，以及从这些状态出发经过任意条 ε 边能够到达的状态的集合。

PS：如果 NFA 没有 ε 转移，就不需要额外计算 ε-closure。

#### 3.3.2 ε-NFA 转 DFA 做题步骤

1. 计算初始状态的 ε-closure，作为 DFA 的初始状态
2. 对每个 DFA 状态集合和每个输入符号，计算 move 后的 ε-closure
3. 若得到新的状态集合，就加入 DFA 状态集合中继续计算
4. 直到不再出现新的状态集合
5. 若某个 DFA 状态集合包含 NFA 的接受状态，则它是 DFA 的接受状态

#### 3.3.3 普通 NFA 转 DFA 做题步骤

1. 令 DFA 的初始状态为 NFA 初始状态集合
2. 对每个状态集合和每个输入符号，求可能到达的 NFA 状态集合
3. 新集合继续展开，直到没有新集合
4. 包含 NFA 接受状态的集合，就是 DFA 接受状态

### 3.4 DFA 化简

**任务**：去掉多余状态，合并等价状态。

多余状态：从开始状态出发无法到达的状态。

等价状态需要同时满足：

1. **一致性条件**：两个状态同为接受状态，或同为非接受状态
2. **蔓延性条件**：对于所有输入符号，它们都转移到等价的状态中

做题步骤：

1. 删除从开始状态不可达的状态
2. 初始划分为接受状态集合和非接受状态集合
3. 检查每个集合内部的状态，若转移目标落入不同集合，则继续拆分
4. 重复拆分，直到不能再拆
5. 每个最终等价类合并成一个状态，弧也要相应合并

### 3.5 DFA 到表驱动实现

DFA 可以转换成状态转换表。

表的含义：给定当前状态和输入符号，可以直接查表得到下一个状态。

特点：

- 时间复杂度：O(输入长度)
- 空间复杂度：O(状态数 × 字母表)
- 优点：状态转移快
- 缺点：字母表很大时表可能很稀疏，占用空间多

PS：实际词法分析器通常选择 DFA，是用空间换速度。

## 4. 词法分析实践：Lex

### 4.1 Lex 的作用

Lex 可以根据词法规范自动生成词法分析器。

整体流程：RE -> NFA -> DFA -> Table

也就是说，程序员写 token 的正则表达式，工具自动生成识别 token 的程序。

### 4.2 多模式匹配规则

当多个模式都能匹配输入时，Lex 通常按以下规则处理：

1. **最长匹配优先**：选择能匹配的最长词素
2. **规则顺序优先**：如果匹配长度相同，选择在规范文件中先出现的规则

### 4.3 关键字识别

关键字和标识符可能冲突。

方法 1：为每个关键字单独写正则表达式，并放在标识符规则之前。

- 优点：直接
- 缺点：自动机更臃肿

方法 2：用同一个正则表达式识别关键字和标识符，再查关键字表区分。

- 优点：自动机更精简
- 缺点：需要额外查表

实际中方法 2 更常用。

# 第四章 语法分析

PS：规范推导：最右 规范规约：最左 
自顶向下：最左 自底向上：最左

## 1. 概念：语法分析

**定义**：语法分析是解析 token 序列，判断输入是否符合语法规则，并生成语法分析结构的过程。

输入：token 序列

输出：语法树 / 语法分析树

常见语法错误：

- else 没有匹配的 if
- 表达式缺少分号
- 表达式结构错误，例如 x * +

语法分析方法分为两类：

1. 自顶向下分析
2. 自底向上分析

## 2. 自顶向下分析

### 2.1 基本思想

**定义**：从文法开始符号出发，反复使用产生式进行推导，尝试构造出与输入串匹配的语法树。

语法树构造方向：从根结点到叶子结点。

对应推导：最左推导。

主要问题：如何根据当前输入符号选择产生式。

### 2.2 自顶向下分析中的问题

自顶向下分析要求推导过程尽量确定，否则可能出现无法选择产生式或无限递归。

常见问题：

1. **左公因子**：同一非终结符的多个候选式有相同开头，导致无法立即选择产生式
2. **左递归**：可能导致自顶向下分析无限递归
3. **二义性**：同一个句子有多棵语法树，推导过程不唯一
4. **ε 产生式**：需要结合 FOLLOW 集判断是否选用空产生式

### 2.3 改写文法

#### 2.3.1 提取左公因子

作用：消除候选式开头相同导致的不确定性。

一般形式：

若 A -> αβ1 | αβ2 | ... | αβn

则改写为：

```text
A  -> αA'
A' -> β1 | β2 | ... | βn
```

含义：把做选择的时间往后推迟。

#### 2.3.2 消除直接左递归

左递归形式：A -> Aα | β

改写为：

```text
A  -> βA'
A' -> αA' | ε
```

一般形式：

若 A -> Aα1 | Aα2 | ... | Aαm | β1 | β2 | ... | βn

则改写为：

```text
A  -> β1A' | β2A' | ... | βnA'
A' -> α1A' | α2A' | ... | αmA' | ε
```

PS：消除左递归后，原来“隐式终止递归”的过程变成了通过 ε 显式终止。

#### 2.3.3 消除间接左递归

基本思想：先把间接左递归转换成直接左递归，再消除直接左递归。

做题步骤：

1. 给所有非终结符排序：A1, A2, ..., An
2. 依次处理 Ai
3. 若 Ai -> Aj... 且 j < i，则用 Aj 的所有候选式替换右部开头的 Aj
4. 若替换后出现直接左递归，则消除直接左递归
5. 删除无用产生式

PS：非终结符排序不同，最终产生式形式可能不同，但文法等价。

#### 2.3.4 消除二义性

二义性可以通过两种方式处理：

1. 改写成等价的无二义文法
2. 添加额外规则，例如优先级、结合性、else 匹配规则

典型例子：Dangling-else。

常用规则：else 总是和最近的尚未匹配的 then 配对。

#### 2.3.5 消除 ε 产生式

基本思想：如果某个非终结符能推出 ε，则在它出现的位置同时考虑“保留”和“删除”两种可能。

做题方式：

对每个产生式 A -> X1X2...Xn：

- 若 Xi 能推出 ε，则 Xi 可以保留，也可以删除
- 若 Xi 不能推出 ε，则必须保留
- 组合出所有可能的新产生式
- 若开始符号能推出 ε，需要补充新的开始符号 S' -> S | ε

### 2.4 FIRST 集和 FOLLOW 集

#### 2.4.1 FIRST 集

**定义**：FIRST(β) 是符号串 β 能推出（0或多步）的串的开头终结符集合
特别的，若 β 能推出 ε，则 ε ∈ FIRST(β)

```
FIRST(α) = { a | α =>* aβ，a ∈ VT，β ∈ V* }
若 α =>* ε，则 ε ∈ FIRST(α)。
```

**计算规则，求每个单符号（终结符或非终结符）的FIRST集（遍历所求符号）：**

1. 若 a 是终结符，则 FIRST(a) = {a} （因为a只能推出自己）
2. 若 A -> ε，则 ε ∈ FIRST(A)
3. 若 A -> a...，则 a ∈ FIRST(A)
4. 若 A -> Y1Y2...Yn，则从 Y1 开始依次加入 FIRST(Yi) - {ε}
5. 只有当前面所有 Yi 都能推出 ε 时，才继续看后面的符号
6. 若所有 Yi 都能推出 ε，则 ε ∈ FIRST(A)

**计算规则，求符号串的FIRST集：**

由单个符号的FIRST集组合

#### 2.4.2 FOLLOW 集

**定义**：FOLLOW(A) 是在某个句型中可能紧跟在非终结符 A 后面的终结符集合
特别的，若 A 可能出现在句型末尾，则 $ ∈ FOLLOW(A)。

```
FOLLOW(A) = { a | S =>* αAaβ，a ∈ VT，α, β ∈ V* }
若 S =>* αA，则 $ ∈ FOLLOW(A)。
```

**计算规则，求每个单符号（非终结符）的FOLLOW集（遍历产生式）**

1. 对开始符号 S，加入 $ 到 FOLLOW(S)
2. 若有产生式 A -> αBβ，则把 FIRST(β) - {ε} 加入 FOLLOW(B)
3. 若 β 能推出 ε，或者 B 位于产生式右部末尾，则把 FOLLOW(A) 加入 FOLLOW(B)
4. 重复直到所有 FOLLOW 集不再变化

PS：ε 不会出现在任何 FOLLOW 集中。

### 2.5 LL(1) 分析

#### 2.5.1 LL(1) 的含义

LL(1)：

- 第一个 L：从左到右扫描输入串
- 第二个 L：产生最左推导
- 1：**推导时**，只向前看一个输入符号就能决定选择哪个产生式

#### 2.5.2 LL(1) 文法条件

若存在产生式 A -> α | β，则上下文无关文法是 LL(1) 的条件为：

1. FIRST(α) ∩ FIRST(β) = ∅
2. 若 ε ∈ FIRST(β)，则 FIRST(α) ∩ FOLLOW(A) = ∅

含义：

- 不同候选式不能以相同终结符开头
- 若某个候选式能推出 ε，则不能和该非终结符的 FOLLOW 集冲突

PS：当前要匹配的输入字符是a，要么选产生式右部的FIRST集包含这个a的产生式；要么选右部FIRST集包含ε（即定义的特殊情况，能推出ε）的产生式，并且这个产生式的左部的FOLLOW集包含a（即我把这个非终结符不要了，但是这个非终结符后面可能推出a）

#### 2.5.3 递归下降预测分析

**定义**：为每个非终结符写一个递归函数，通过函数调用模拟推导过程。

特点：

- 手写实现
- 每个非终结符对应一个函数
- 通过 if-else 或 switch 根据 lookahead 选择产生式
- 可基于 LL(1)，也可通过更多向前看实现 LL(k)

开发流程：

1. 消除二义性
2. 消除左递归
3. 提取左公因子
4. 根据文法构造转换图
5. 简化转换图
6. 根据转换图编写递归函数

#### 2.5.4 LL(1) 预测分析表

预测分析表 M[A, a] 表示：

当栈顶是非终结符 A，当前输入符号是 a 时，应选择哪个产生式。

构造规则：

对每个产生式 A -> α：

1. 对 FIRST(α) 中的每个终结符 a，把 A -> α 填入 M[A, a]
2. 若 ε ∈ FIRST(α)，则对 FOLLOW(A) 中的每个符号 b，把 A -> α 填入 M[A, b]
3. 其他空白项表示错误

表格组成：行头为大写字母，列头为小写字母

#### 2.5.5 LL(1) 表驱动分析

组成：

- 预测分析表（存储）
- 分析栈（内存）
- 输入缓冲区（输入）
- 分析程序（CPU）
- 输出流（输出）

状态变化：`$S, w$ -> $,$` 

分析动作：

1. 若栈顶终结符等于当前输入符号，则匹配并弹栈，输入前进
2. 若栈顶是终结符但不匹配，则报错
3. 若栈顶是非终结符 A，则查 M[A, lookahead]
4. 若表项为空，则报错
5. 若表项为 A -> Y1Y2...Yk，则弹出 A，并将右部反序压栈

表格4栏：步骤、Stack、输入字符串、Action

#### 2.5.6 LL(1) 错误恢复

恐慌模式：

- **把 FOLLOW(A) 中的符号作为 A 的同步符号 synch，其余空白为error**
- 若 M[top, lookahead] 为空/error，则**跳过当前输入符号**
- 若 M[top, lookahead] 为synch，**则弹出栈顶非终结符**

## 3. 自底向上分析

### 3.1 基本思想

**定义**：从输入符号串开始，逐步归约，直到归约到文法开始符号。

语法树构造方向：从叶子结点到根结点。

规约顺序：最左规约/规范规约

主要问题：如何确定当前应归约的子串。

### 3.2 移进-归约分析

移进-归约分析使用符号栈，从左到右扫描输入。

动作：

- **移进**：把当前输入符号压入栈中
- **归约**：当栈顶形成某个产生式右部时，用产生式左部替换它
- **接受**：输入结束且栈中只剩开始符号
- **报错**：无法移进或归约

与 LL(1) 的对比：

- LL(1)：自顶向下，动作是 match / derive （匹配/推导）
- 移进-归约：自底向上，动作是 shift / reduce （移近/规约）

### 3.3 算符优先分析

#### 3.3.1 算符文法

**定义**：若上下文无关文法中任一产生式右部都没有两个非终结符相邻，并且不含 ε 产生式，则称为算符文法。

**优点：**

- 分析速度快
- 特别适合表达式分析

**缺点：**

- 适用范围窄
- 只能用于算符文法 / 算符优先文法
- 不是规范归约
- 归约时不关心非终结符名字，可能错误归约
- 有时错误句子也可能被错误地归约成功

#### 3.3.2 算符优先分析

基本思想：只定义终结符之间的优先关系，并用这些关系指导移进或归约，适用于算符文法。

和规范归约的区别：

- 规范归约：每次归约句柄（最左直接短语）
- 算符优先分析：每次归约最左素短语（至少包含一个小写字母）

#### 3.3.3 最左素短语

**素短语**：至少包含一个终结符，并且除自身外不包含其他素短语的短语。

**最左素短语**：最左边的素短语。

#### 3.3.4 相邻终结符和优先关系

算符优先分析只比较终结符之间的优先关系。

三种优先关系：

- a ≺ b：a 优先级低于 b
- a ≡ b：a 优先级等于 b
- a ≻ b：a 优先级高于 b

注意：

- a ≺ b：通常表示应该继续移进 b
- a ≡ b：通常表示二者处于同一结构中，例如括号配对
- a ≻ b：通常表示栈顶附近已经形成可归约部分

#### 3.3.5 算符优先关系表

算符优先分析依赖算符优先关系表。

表的行：栈中最右边的终结符。

表的列：当前输入终结符。

表项含义：

- ≺ 或 ≡：移进当前输入符号
- ≻：归约栈顶附近的最左素短语
- 空白：出错

PS：比较时不是看栈顶符号，而是看**栈中最靠右的终结符**。

#### 3.3.6 算符优先分析过程

基本过程：

1. 找到栈中最右边的终结符 a
2. 设当前输入符号为 b
3. 查优先关系表中 a 和 b 的关系
4. 若 a ≺ b 或 a ≡ b，则移进 b
5. 若 a ≻ b，则从栈顶向左寻找最左素短语的左边界，并进行归约
6. 若栈中为 $N，输入为 $，其中 N 为某个非终结符，则接受

找最左素短语边界：

- 右边界：由 a ≻ b 触发，说明栈顶附近应该归约
- 左边界：从栈顶向左找第一个 ≺ 关系
- 左边界和右边界之间的部分就是要归约的最左素短语

#### 3.3.7 归约时匹配规则

算符优先分析归约时，要检查是否有产生式右部和最左素短语匹配。

匹配规则：

1. 符号个数相同
2. 终结符的名字和位置必须相同
3. 非终结符的位置必须相同
4. **非终结符的名字不要求相同！**

若存在满足条件的产生式，就用该产生式归约。

若不存在满足条件的产生式，则出错。

#### 3.3.8 优先函数

算符优先关系表可能占用较多空间，优化函数用于优化。

可以用两个优先函数 f 和 g 代替优先关系表。

对终结符 a 和 b：

- 若 a ≡ b，则 f(a) = g(b)
- 若 a ≺ b，则 f(a) < g(b)
- 若 a ≻ b，则 f(a) > g(b)

优点：

- 节省空间

缺点：

- 原本表中空白的错误项，可能被函数值强行比较出大小
- 因此不如优先关系表容易准确发现错误

### 3.4 LR 分析

#### 3.4.1 LR 分析概念

LR 分析是一类自底向上的规范归约方法。

LR(k) 含义：

- L：从左到右扫描输入
- R：构造最右推导的逆过程，即最左归约
- k：**规约时**，向前看 k 个输入符号

特点：

- 适用范围比 LL 和算符优先分析更广
- 分析速度快
- 能较早发现错误
- 构造分析器工作量大

#### 3.4.2 LR(0) 项目

**定义**：在产生式右部某个位置加一个圆点，得到 LR(0) 项目

例子：A -> XYZ 对应四个项目：

```text
A -> ·XYZ
A -> X·YZ
A -> XY·Z
A -> XYZ·
```

圆点含义：

- 圆点左边：已经识别的部分
- 圆点右边：待识别的部分
- 圆点到最右边：句柄已经形成，可以归约

项目类型：

- 移进项目：圆点后是终结符
- 待约项目：圆点后是非终结符
- 归约项目：圆点在最右端
- 接受项目：S' -> S·

#### 3.4.3 拓广文法

对原文法 G[S] 增加新的开始符号 S' 和产生式 S' -> S。

目的：让接受项目唯一，避免把右部出现的 S 和真正的开始符号混淆。

#### 3.4.4 CLOSURE 函数

**定义**：若 I 是项目集，则 CLOSURE(I) 按以下规则扩充：

1. I 中的项目都属于 CLOSURE(I)
2. 若 A -> α·Bβ 属于 CLOSURE(I)，且 B 是非终结符，则把每个 B -> ·γ 加入 CLOSURE(I)
3. 重复直到项目集不再扩大

#### 3.4.5 GOTO 函数

**定义**：GOTO(I, X) 表示项目集 I 识别符号 X 后到达的项目集。

计算方式：

1. 找出 I 中所有形如 A -> α·Xβ 的项目
2. 将圆点越过 X，得到 A -> αX·β
3. 对这些项目求 CLOSURE

#### 3.4.6 LR(0) 项目集 DFA

构造步骤：

1. 初始状态 I0 = CLOSURE({S' -> ·S})
2. 对每个项目集 I 和每个文法符号 X 计算 GOTO(I, X)
3. 若得到新项目集，则加入状态集合
4. 重复直到没有新项目集

PS：LR(0) DFA 识别的是文法的可行前缀。

#### 3.4.7 LR(0) 分析表

LR 分析表分为：

- ACTION 表：面对终结符时执行移进、归约、接受或报错
- GOTO 表：面对非终结符时转到哪个状态

LR(0) 构造规则：

1. 若 A -> α·aβ 在状态 k 中，且 GOTO(k, a) = j，则 ACTION[k, a] = Sj
2. 若 A -> α·Bβ 在状态 k 中，且 GOTO(k, B) = j，则 GOTO[k, B] = j
3. 若 A -> α· 在状态 k 中，则对所有终结符和 $ 填归约 rj
4. 若 S' -> S· 在状态 k 中，则 ACTION[k, $] = acc

PS：LR(0) 的 0 体现在归约时不看任何输入符号（即一行都是reduce）

#### 3.4.8 LR(0) 冲突

项目集冲突：

- **移进-归约冲突**：同一项目集中既有移进项目，又有归约项目
- **归约-归约冲突**：同一项目集中有多个归约项目

LR(0)文法：若 LR(0) 项目集规范族中没有这两类冲突，则该文法是 LR(0) 文法。

#### 3.4.9 SLR(1)

基本思想：在 LR(0) 基础上，用 FOLLOW 集限制归约范围。

规则：

若状态中有归约项目 A -> α·，只在输入符号属于 FOLLOW(A) 时才归约。

作用：

- 比 LR(0) 更精确
- 能解决一部分 LR(0) 冲突
- 但 FOLLOW(A) 仍然太粗，不能解决所有冲突

#### 3.4.10 LR(1)

基本思想：为每个项目增加一个向前搜索符。

LR(1) 项目形式：[A -> α·β, a]

含义：若项目是 [A -> α·, a]，则只有当前输入符号是 a 时，才用 A -> α 归约。

LR(1) 的 CLOSURE：

若 [A -> α·Bβ, a] 在项目集中，且 B -> γ 是产生式，则对 b ∈ FIRST(βa)，加入 [B -> ·γ, b]。

特点：

- 比 SLR(1) 更精确
- 分析能力更强
- 状态数可能很大

#### 3.4.11 LALR(1)

基本思想：合并 LR(1) 项目集中“心”相同的项目集，减少状态数量

心：LR(1) 项目中去掉向前搜索符之后的 LR(0) 项目部分。

合并方式：同心项目集合并，向前搜索符集合取并集。

特点：

- 状态数接近 LR(0) / SLR(1)
- 分析能力接近 LR(1)
- 若合并同心集后产生新冲突，则不能用 LALR(1)
- Yacc / Bison 默认使用 LALR(1)

#### 3.4.12 四类 LR 方法对比

**归约时**，判定方式：

- LR(0)：不看输入符号，只靠当前状态决定是否归约
- SLR(1)：看一个输入符号，但归约条件是 FOLLOW(A)
- LR(1)：看一个输入符号，并且每个项目有自己的精确向前搜索符
- LALR(1)：合并 LR(1) 同心项目集，在状态数和分析能力之间折中

分析能力：

LR(0) < SLR(1) < LALR(1) < LR(1)

PS：若一个文法是 LR(0)，则一定是 SLR(1)，也一定是 LR(1)；反过来不一定。

#### 3.4.13 二义性文法的 LR 分析

二义性文法通常不能直接成为无冲突 LR 文法。

处理方式：

1. 改写成无二义文法
2. 保留二义文法，但添加优先级和结合性规则

表达式文法常用额外规则：

- * 的优先级高于 +
- * 和 + 都左结合

Dangling-else 常用额外规则：

- else 总是和最近的 then 配对

#### 3.4.14 LR 错误恢复

若 LR 分析表无冲突，输入中的语法错误会在分析表空白项处被发现。

错误恢复方式：

1. 恐慌模式：跳过输入或弹栈，直到回到可继续分析的状态
2. 短语级错误恢复：在分析表的错误项中填入特定错误处理例程

不同 LR 方法发现错误的早晚一般为：

LR(0) >= SLR(1) >= LALR(1) >= LR(1)

含义：LR(1) 通常能更早发现错误。

# 第五章 语法制导翻译

PS：第五章不是编译阶段，是一种方法，可以用于两个阶段：语义分析+中间代码生成

## 1. 语法制导翻译

**定义**：在语法分析的基础上，根据文法产生式所**附带的语义规则**进行翻译。

主要用途：

- 语义分析
- 中间代码生成

语义分析的输入和输出：

- 输入：语法分析得到的语法树
- 输出：输出取决于你用它做什么（语义分析：带有语义信息的语法树+符号表；中间代码生成：中间IR）

进行语义分析的常见任务：

- 类型检查
- 变量是否声明
- 函数调用参数是否匹配
- 数组下标、运算对象等是否合法

## 2. 语法制导定义 SDD

**语法制导定义**：Syntax-Directed Definition，SDD = 上下文无关文法 + 属性 + 语义规则。

其中：

- 属性：附着在**文法符号**上的语义信息
- 语义规则：附着在**产生式**上的计算规则，用来1.计算属性值 2.执行其他动作，形式为函数或代码块

例子：

产生式 E -> E1 + T 可以附带语义规则：E.val = E1.val + T.val

## 3. 属性

### 3.1 综合属性

**综合属性**：一个结点的属性值由它的**子结点**属性值计算得到。（定义不准确）

信息流向：

- 从子结点流向父结点
- 自底向上

典型例子：

- 表达式的**值**
- 表达式的**类型**
- 子树生成的中间代码

### 3.2 继承属性

**继承属性**：一个结点的属性值由它的**父结点**或**兄弟结点**属性值计算得到。（定义不准确）

信息流向：

- 从父结点流向子结点
- 或从左兄弟流向右兄弟
- 通常体现上下文信息

典型例子：

- 声明语句中的类型向变量名传播
- 符号表环境
- 控制流中的标号信息

### 3.3 属性的约定

终结符：只有综合属性，属性值通常由词法分析器提供

非终结符：可以有综合属性，也可以有继承属性

开始符号：没有继承属性

PS：综合属性更像“子树算出结果交给父结点”；继承属性更像“上下文把信息传给当前结点”。

## 4. 注释语法分析树

**注释语法分析树**：语法分析树+每个节点的属性值标出

## 5. 依赖图和属性求值顺序

**依赖图**：描述了属性之间的求值依赖关系

若属性 b 的计算需要用到属性 a，则有一条边：

a -> b

含义：必须先计算 a，再计算 b。

**属性求值顺序：**

- 必须满足依赖图中的依赖关系
- 等价于对依赖图做拓扑排序

若依赖图中存在环：

- 属性之间相互依赖
- 无法确定合法的计算顺序
- 该 SDD 不能正常求值

## 6. 抽象语法树

**抽象语法树**：Abstract Syntax Tree，简称 AST。

特点：

- 去掉对语义无关的语法细节
- 保留程序结构的核心信息
- 比完整语法分析树更适合后续语义分析和代码生成

常被省略的内容：

- 括号
- 分隔符
- 某些只用于消除二义性的中间非终结符

PS：语法分析树更贴近文法推导过程；抽象语法树更贴近程序真实结构。

## 7. S-属性定义

**S-属性定义**：SDD，只包含综合属性

特点：

- 所有属性都从子结点传向父结点
- 可以自底向上计算
- 适合与 LR 分析结合（刚好都是自底向上）

求值方式：

- 按语法树后序遍历计算
- 或在自底向上的归约过程中计算

## 8. L-属性定义

**L-属性定义**：SDD，包含综合属性+受限制的继承属性

对产生式 A -> X1 X2 ... Xn，Xi 的继承属性只能依赖：

- A 的继承属性（因为A的综合属性通常还没计算完）
- Xi 左边符号 X1, X2, ..., Xi-1 的属性（左边的所有属性已经计算完了）
- Xi 自身的属性，但不能形成循环依赖（可以来源自己但是不能成环）

特点：

- 按语法书深度优先，从左到右
- 适合与自顶向下分析结合
- 比 S-属性定义表达能力更强

## 9. SDD 与 SDT

### 9.1 SDD

SDD 是一种说明性定义。

特点：

- 说明属性依赖关系，**不强制规定具体执行时机**

### 9.2 SDT

定义：Syntax-Directed Translation。SDT = 上下文无关文法+语义动作/规则（嵌入产生式）

特点：

- **说明执行时间（根据在产生式中的位置）**

## 10. S-属性翻译方案

S属性SDD->S属性SDT中，语义动作位置：**产生式右部末尾**。

原因：

- S-属性只依赖子结点属性
- 只有当产生式右部都分析完时，子结点属性才都可用

在 LR 分析中的实现方式：

- 分析栈保存文法符号和状态
- 语义栈保存对应属性值
- 每次归约时，根据产生式右部属性计算左部属性

## 11. L-属性翻译方案

L属性SDD->L属性SDT中，语义动作位置：**如下规则**。

基本原则：

1. 计算某个非终结符继承属性的动作，放在该**非终结符之前**
2. 计算产生式左部综合属性的动作，放在**产生式右部末尾**

原因：

- 继承属性要在进入该非终结符之前准备好
- 综合属性要在右部符号都处理完之后才能计算

在递归下降分析中的实现方式：

- 继承属性作为函数参数传入
- 综合属性作为函数返回值返回
- 中间属性可以用局部变量保存

## 12. 在 LR 分析中实现属性翻译

### 12.1 实现 S-属性定义

S-属性定义在 LR 分析中最容易实现。

原因：

- LR 分析在归约时，产生式右部已经出现在栈顶
- 右部符号的综合属性已经可以取得
- 此时可以直接计算左部综合属性

### 12.2 实现 L-属性定义

L-属性定义在 LR 分析中更复杂。

主要困难：

- 继承属性需要在分析某个符号之前计算
- LR 分析的语义动作通常在归约时执行
- 嵌在产生式中间的动作不一定能直接等到归约时再执行

常见处理方式：

- 用标记非终结符把中间动作改写成产生式末尾动作
- 在语义栈中保存和查找需要的继承属性
- 必要时引入空产生式来触发语义动作

PS：LR 分析天然适合“归约时算综合属性”；遇到“提前传递继承属性”时，就需要额外改写或栈管理。

## 13.题型总结

**1.属性类型判断**

判断A.a，找赋值语句A.a=xxx(在左边或被赋值)，然后看A的位置，A在产生式左边为综合，右边为继承

**2.写注释语法分析树**

语法树+标明属性值

**3.SDD类型判断**

​	1.找有哪些属性，只有综合为S-SDD

​	2.若有继承，且满足限制则为L-SDD

**4.递归下降预测翻译**

​	1.找每个非终结符的继承属性和综合属性

​	2.每个非终结符一个函数，继承属性为参数，综合属性为返回值

​	3.将该非终结符涉及到的所有产生式的所有非终结符的所有属性先声明列出

​	4.根据不同表达式分支，按部就班

**5.SDD转SDT**

​	综合属性放最后，继承属性放非终结符前面。

**6.依赖图 / 属性求值顺序**

​	SDD的语义规则决定了依赖图，依赖图决定了求值顺序

**7.抽象语法树**

​	算符可以改就改，不能改就普通语法树画法（但也有差别，去除多余关键字）

# 第六章 中间代码生成

## 1. 中间代码生成

**中间代码生成**：把语法树翻译成中间表示。

输入：语法树 / 抽象语法树。

输出：中间表示 IR。

作用：

- 连接源语言和目标机器语言
- 降低代码生成难度
- 便于进行机器无关优化

## 2. 中间表示 IR

**中间表示**：Intermediate Representation，简称 IR。

### 2.1 高级中间表示

典型形式：

- 抽象语法树 AST
- 有向无环图 DAG

特点：

- 接近源程序结构
- 适合语义分析、类型检查等任务

### 2.2 低级中间表示

典型形式：

- 三地址码 TAC

特点：

- 接近机器指令
- 适合后续代码优化、寄存器分配、目标代码生成

## 3. AST 和 DAG

### 3.1 AST

AST抽象语法树，表示程序的核心语法结构（可以利用语法制导翻译方法，生成中间代码AST，语义动作为new node）

特点：

- 保留运算、语句、控制结构等核心信息
- 去掉括号、分隔符等对语义无关的细节

### 3.2 DAG

DAG 可以共享相同的子表达式。

作用：

- 表示表达式计算关系
- 避免重复表示公共子表达式
- 有利于公共子表达式优化

例子：

a + a * (b - c) + (b - c) * d 中，b - c 出现两次。

在 AST 中通常会出现两棵相同子树；在 DAG 中可以共享同一个 b - c 结点。

### 3.3 DAG 的值编码

值编码思想：

- 用一个记录数组存放 DAG 结点
- 每个结点有一个编号
- 叶子结点记录标识符或常量
- 内部结点记录运算符和左右子结点编号

PS：值编码本质上是用表格形式表示 DAG，便于判断某个表达式结点是否已经出现过。

## 4. 三地址码 TAC

**三地址码**：一条指令右侧最多只有一个运算符的中间代码形式（关键不是3个地址，是最多一个运算符，一次运算）

两个要素：地址和指令

### 4.1 地址

三地址码中的地址可以是：

- 名字：源程序中的变量名，通常对应符号表项
- 常量：字面量常量
- 临时变量：编译器生成的中间结果

### 4.2 常见指令形式

常见三地址指令：

- x = y op z
- x = op y
- x = y
- goto L
- if x goto L
- ifFalse x goto L
- if x relop y goto L
- param x
- call p, n
- y = call p, n
- return y
- x = y[i]（i代表内存单元位置，不是数组位置！！！）
- x[i] = y
- x = &y
- x = *y
- *x = y

## 5. 三地址码的表示方式

### 5.1 三元式

三元式字段：

- op
- arg1
- arg2

特点：

- 没有显式 result 字段，用指令位置表示运算结果，其他指令通过位置引用该结果

缺点：

- 如果移动指令位置，所有引用该位置的指令都要修改

### 5.2 间接三元式

间接三元式 = 三元式 + 指向三元式的指针表

特点：

- 在三原式的基础上，优化时可以重排指针表，而不移动三元式本身

### 5.3 四元式

四元式字段：

- op
- arg1
- arg2
- result

特点：

- 用显式 result 保存结果，移动指令时，使用临时变量的指令不需要修改

# 第八章 目标代码生成

## 1. 概念：目标代码生成

**目标代码生成**：把中间表示翻译成特定目标机器上的目标代码。

输入：优化后或未优化的中间表示。

输出：

- 目标机器语言
- 目标汇编语言

主要任务：

- **指令选择**
- **寄存器分配与指派**
- **指令排序/调度**
- 机器相关**优化**

目标：

- 生成的代码尽量**短**
- 生成的代码执行尽量**快**
- 尽量利用**寄存器**，减少访存次数

## 2. 指令选择

**指令选择**：选择合适的目标机器指令来实现中间代码操作。同一个中间代码操作可能有多种目标代码实现。

## 3. 寄存器分配与指派

目标：高效利用寄存器，减少内存访问。

包含两个问题：分配+指派

PS：分配回答“要不要放寄存器”；指派回答“放哪个寄存器”。

### 3.1 寄存器分配

**寄存器分配**：决定程序中哪些变量或临时值应该放在寄存器中。

关注点：

- 哪些值访问频繁
- 哪些值在当前程序点仍然有用
- 寄存器数量是否足够

### 3.2 寄存器指派

**寄存器指派**：给已经决定放入寄存器的值分配具体寄存器。

关注点：

- 使用哪个具体寄存器
- 是否符合目标机器调用约定
- 是否和其他值的活跃区间冲突

## 4. 指令排序

**指令排序/调度**：重新安排指令执行顺序，在保持**语义不变**的前提下提高执行效率。

主要目的：

- 减少流水线停顿（因为依赖关系）
- 提高指令级并行性ILP
- 避免过早使用尚未准备好的结果

限制：

- 不能改变数据依赖
- 不能改变控制依赖导致的程序语义

PS：指令排序能调整的是“无依赖或不影响语义的顺序”，不是任意打乱指令。

## **5.非重点**

## 6. 代码生成器

本章讨论的是基于基本块的代码生成器。

输入：四元式中间代码。

输出：目标机器的汇编代码。

重点问题：

- 如何在基本块内分配寄存器
- 如何减少访存次数
- 如何根据变量后续是否还会使用来释放寄存器

## 7. 寄存器分配原则

总原则：

- 寄存器执行代价最小，希望将尽可能多的运算对象保存在寄存器中
- 但寄存器数量有限，需要按一定原则分配

基于基本块的寄存器分配原则：

1. 生成某变量的目标代码时，尽量让它的值或中间结果保留在寄存器中
2. 进入基本块时，认为所有寄存器空闲；到基本块出口时，把仍然活跃且只在寄存器中的变量存回内存
4. 基本块内，后面不再引用的变量所占寄存器应尽早释放

PS：寄存器分配的核心是“把将来还要用的值留在寄存器里，把不再用的值尽快释放”。

## 8. 待用信息和活跃信息

### 8.1 定值、引用、活跃

在四元式 **i: A := B op C** 中：

- A 被定值
- B 和 C 被引用
- i 是 A 的定值点，也是 B、C 的引用点

**活跃（前提要在某点i）：** 若定值变量的值在i之后的代码序列被引用，则称**变量在i点是活跃**的。

### 8.2 待用信息

**待用信息**：某变量当前值下一次会在基本块中的哪条四元式被引用。

若 A 在四元式 i 中被定值，并且之后在四元式 j 中被引用，且 i 到 j 之间没有对 A 的重新定值，则 j 是 i 中 A 的待用信息。

含义：

- 待用：后面还会用，最好保留
- 非待用：后面不再用，可以释放

PS：待用信息只在基本块内考虑；基本块出口之后是否还会用，需要靠活跃变量信息。

## 9. 基本块内求待用信息的表法

目标：为每条四元式附加结果变量、左操作数、右操作数的待用信息和活跃信息。

初始设置：

1. 基本块出口活跃的变量，活跃信息置为活跃
2. 基本块出口不活跃的变量，活跃信息置为非活跃
3. 所有变量的待用信息初始置为非待用
4. 通常用户变量在基本块出口认为活跃，临时变量认为非活跃

从基本块最后一条四元式开始，倒着处理每条四元式 i: A := B op C：

1. 把符号表中 A 的待用和活跃信息附加到四元式 i 的结果栏
2. 将 A 的待用信息置为非待用，活跃信息置为非活跃
3. 把符号表中 B 和 C 的待用和活跃信息附加到四元式 i 的操作数栏
4. 将 B 和 C 的待用信息置为 i，活跃信息置为活跃

注意：这四步顺序不能颠倒，因为 A、B、C 可能是同一个变量。

PS：倒着扫的原因是，只有从后往前看，才知道“这个变量下一次在哪里被用”。

## 10. 寄存器描述和地址描述

### 10.1 寄存器描述 RVALUE

RVALUE 用来记录每个寄存器当前保存了哪些变量的值。

例子：

- RVALUE[Ri] = {A}：Ri 中保存变量 A 的值
- RVALUE[Ri] = ∅：Ri 当前空闲
- RVALUE[Ri] = {B, C}：Ri 中的值同时是 B 和 C 的值

多个变量共占一个寄存器常见于复写语句，例如 B := C。

### 10.2 地址描述 AVALUE

AVALUE 用来记录某变量当前值存放在哪里。

可能位置：

- 某个寄存器
- 内存单元
- 同时在寄存器和内存中

例子：

- AVALUE[A] = {Ri}：A 的值只在 Ri 中
- AVALUE[B] = {Ri, B}：B 的值既在 Ri 中，也在内存 B 中
- AVALUE[C] = {C}：C 的值只在内存 C 中

PS：RVALUE 是“寄存器里有什么”；AVALUE 是“变量在哪里”。

## 11. GETREG 寄存器分配算法

GETREG 的作用：为四元式 i: A := B op C 选择一个寄存器 R，用来保存 A 的结果值。

选择顺序：

1. 如果 B 独占某个寄存器 Ri，并且 B 与 A 是同一标识符，或 B 之后不再被引用，则选择 Ri
2. 否则，如果有空闲寄存器 Ri，则选择 Ri
3. 否则，释放某个寄存器 Ri

释放寄存器时优先选择：

- 寄存器中变量的值已经在内存中
- 或者寄存器中的变量在基本块中下一次引用最远

如果被释放寄存器中的某个变量 M 不在内存中，且以后还需要它：

- 生成 ST 指令，把 M 存回内存
- 修改 AVALUE[M]
- 修改 RVALUE[Ri]

PS：GETREG 的本质是选择“最划算”的寄存器，优先复用不再需要的寄存器。

## 12. 基本块代码生成算法

对基本块中的每条四元式 i: A := B op C，顺序生成目标代码。

步骤：

1. 调用 GETREG，为 A 的结果选择寄存器 R
2. 根据 AVALUE[B] 和 AVALUE[C] 找到 B 和 C 当前值的位置 B' 和 C'
3. 若 B' 不在 R 中，则生成 LD R, B'
4. 生成目标运算指令 OP R, C'
5. 更新 AVALUE[A] = {R}
6. 更新 RVALUE[R] = {A}
7. 若 B 或 C 后面非待用且非活跃，则释放它们占用的寄存器
8. 到基本块出口时，若活跃变量在寄存器中但不在内存中，则生成 ST 指令存回内存

例子思路：

对 T := A - B：

- 若 R1 空闲，选 R1
- 生成 LD R1, A
- 生成 SUB R1, B
- 记录 T 在 R1 中

PS：基本块代码生成算法依赖待用信息和活跃信息；没有这些信息，就不知道哪些寄存器能安全释放。

# 第九章 代码优化

## 1. 概念：代码优化

**代码优化**：对代码进行语义保持的**等价变换**，使变换后的代码**效率更高**。

优化目标：

- 减少运行时间
- 减少存储空间

语义保持：

- 优化前后程序的运行**结果**必须一致
- 不能为了效率改变**程序含义**

需要权衡：

- 时间效率和空间效率
- 编译器效率和目标代码效率

## 2. 优化级别

### 2.1 源代码优化

在源程序级别进行优化。

特点：

- 接近程序员写的代码
- 可以利用源语言高级结构

### 2.2 中间代码优化

在中间表示上进行优化。

特点：

- 通常与具体机器无关
- 是编译器优化的重要阶段

### 2.3 目标代码优化

在目标代码上进行优化。

特点：

- 依赖具体机器

## 3. 优化分类

### 3.1 局部优化

作用范围：一个基本块内部。

特点：

- 不跨越控制流分支
- 常利用基本块 DAG 进行优化

### 3.2 循环优化

作用范围：循环内部。

特点：

- 对程序效率影响很大
- 基于控制流分析

### 3.3 全局优化

作用范围：整个程序范围内，过程 / 函数。

特点：

- 可以跨基本块优化
- 基于数据流分析

### 3.4 窥孔优化

作用范围：一个很小的滑动窗口进行优化。

## 4. 常见优化技术

### 4.1 删除公共子表达式

若某个表达式 E 已经计算过，并且之后 E 中变量的值都没有改变，则再次出现的 E 是公共子表达式。

优化方式：不重复计算 E，直接复用前一次计算结果

例子：

若 T1 = 4 * I 已经计算过，且 I 没有改变，则后面的 T4 = 4 * I 可以改为 T4 = T1。

### 4.2 常量折叠

**常量折叠**：如果运算分量都是编译期已知常量，则在编译期直接算出结果。

例子：

4 * 1 可以直接变成 4。

### 4.3 常量传播

**常量传播**：若变量的值已知为常量，则在后续引用处用该常量替换。

例子：

若 T1 = 4，则 T4 = T1 可以变成 T4 = 4。

### 4.4 复写传播

**复写传播**：若有 A = B，且之后 A、B 的值都未改变，则后面对 A 的引用可以改为对 B 的引用。

作用：

- 减少临时变量
- 为删除无用赋值创造条件

### 4.5 删除死代码

死代码常见情况：

- 变量被赋值后从未被引用
- 变量赋值后尚未被引用又被重新赋值
- 某个赋值只被无用变量自身引用

优化方式：

- 删除这些不会影响程序结果的赋值或代码

PS：很多优化会互相促进，例如复写传播后，原来的赋值可能变成死代码。

## 5. 局部优化

**局部优化**：在一个基本块内部进行优化。

基本流程：

1. 划分基本块
2. 构造基本块的 DAG
3. 根据 DAG 进行优化
4. 从优化后的 DAG 重新生成代码

## 6. 基本块

**基本块**：一段顺序执行的**语句序列**，只有**一个入口和一个出口**。

特点：

- 只能从入口语句进入
- 除最后出口处外，中间不会跳出
- 执行到入口后，会顺序执行到出口

## 7. 基本块的划分

### 7.1 找入口语句

入口语句包括：

1. 程序的**第一条语句**
2. 条件转移或无条件转移语句的**目标语句**
3. 紧跟在**条件转移语句后面的语句**（无条件转移语句后面的语句不一定是入口）

### 7.2 构造基本块

从每个入口语句开始，向后收集语句，直到：

1. 下一个**入口**语句之前

2. 或遇到**转移**语句并包括该转移语句

3. 或遇到**停止**语句并包括该停止语句

没有被纳入任何基本块的语句：

- 不可达，可以删除

## 8. 基本块的 DAG

基本块 DAG 是带有标记的**有向无环图**。

结点含义：

- 叶子结点：变量或常量的值
- 内部结点：运算符作用于子结点后的结果
- 附加标识符：表示哪些变量当前具有该结点代表的值

## 9. 利用 DAG 进行局部优化

DAG 可以支持的优化：

- 删除公共子表达式
- 常量折叠
- 复写传播
- 删除无用赋值

基本思想：

- 相同表达式共享同一个 DAG 结点
- 变量名作为附加标识符挂在结点上
- 若某个临时变量在基本块出口之后不再被引用，可以删除其附加标识符
- 最后只为仍然需要的结点生成代码

PS：DAG 优化的关键是“值相同就用同一个结点表示”，从而自然暴露公共子表达式和无用赋值。

## 10. 流图

**流图**：在**基本块集合**上加入**控制流**边形成的有向图。

结点：基本块

首结点：包含程序第一条语句的基本块

边的建立条件：

1. Bj 在程序中紧跟 Bi 后面，且 Bi 的出口不是无条件跳转或停止语句
2. Bi 的出口是转移语句，并且转移目标是 Bj 的入口语句

## 11. 循环优化

循环优化对程序效率影响很大。

原因：循环体中的代码可能执行很多次，一次小优化会被放大很多次

常见循环优化：

1. 代码外提
2. 强度削弱
3. 变换循环控制条件
4. 归纳变量消除

## 12. 代码外提

**代码外提**：把循**环不变运算**移到循环前面，使其**只计算一次**。

循环不变运算：

- 运算结果不依赖循环执行次数
- 运算分量是常量，或在循环外定值且循环中不改变

## 13. 强度削弱

**强度削弱**：把**开销较大的运算**替换成开销较小的等价运算。

典型例子：

- 把乘法变成加法
- 把指数运算变成乘法

循环中常见情况：

若 T1 = 4 * I，且 I 每次循环加 1，则 T1 每次循环只需要加 4。

​	只有条件转移后的语句可以作为开头

​	注意！：运算符左右是有严格顺序的，包括+

​	其余变量写在节点右边

​	注意常量传播直接将最终结果花在图中
